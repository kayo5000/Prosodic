# Prosodic — Build Plan

**Dated:** 2026-08-16. One dependency-ordered sequence covering both the scaffold/architecture work and the remaining feature/product work — merged into a single order so nothing gets built once against a structure that's about to change underneath it, then has to be redone. ## Phase 2 — Backend contract + quality tooling (after Phase 1 settles) ✅

Everything here is generated from or checked against the backend's *final* shape — this is the phase Khris's own example was about.

- **2a. ✅ DONE. OpenAPI spec.** `docs/openapi.yaml`, OpenAPI 3.0.3, sourced from the actual live routes in their final `domain/`/`application/`/`infrastructure/` locations — 21 real paths, 22 operations (`/corrections` has GET+POST), confirmed to be the complete real set by diffing against `api.app.url_map.iter_rules()` directly (43 raw Flask rules incl. the duplicate explicit-OPTIONS handlers and Flask's own auto-added OPTIONS, which collapse to exactly 21 real paths). Validated structurally with `openapi-spec-validator` (clean pass) after fixing two real authoring bugs it caught: (1) `exclusiveMinimum: 0` — OpenAPI 3.0 uses JSON Schema Draft 4 semantics where `exclusiveMinimum` is a boolean flag paired with `minimum`, not a number (that's 3.1/2020-12 style) — fixed to `minimum: 0, exclusiveMinimum: true` on the 3 `bpm` fields; (2) three unquoted YAML flow-mapping description strings containing commas (e.g. `description: HS256 JWT, 30-day expiry`) were silently parsed as an extra bogus dict key instead of one string — fixed by quoting. Then verified against **real Flask-test-client responses**, not just read from source, for the highest-risk endpoints (`/health`, `/mastery`, `/auth/register`, `/auth/me`, `/suggest-family`, `/autofill`, `/thesaurus/synonyms`, `/corrections`, `/suggest`, `/analyze`) — caught one real spec inaccuracy this way: a speculative `is_slant_bridge` boolean on `FamilySuggestion` (inferred from a docstring's wording, not the actual code) doesn't exist in the real response, which is just `{color_id, score}`. Removed before finalizing. `requirements-dev.txt` created (pytest-cov, mypy, pyyaml, openapi-spec-validator — dev/CI-only, not shipped in the app's own `requirements.txt`).
- **2b. ✅ DONE. mypy on the backend.** `mypy.ini` — permissive baseline (no `--strict`; this codebase had ~zero prior annotations), scoped to `domain/`, `application/`, `infrastructure/`, `api.py`, `veil_revival_routes.py`, `cantos/`, `behavior/`, `analysis/` (the layers Phase 1 just settled — `mobile/`, `tests/`, and one-off scripts excluded). First run: **66 errors across 21 of 59 checked files. Final: 0.** Every fix was either a real type annotation, a documented runtime invariant (an `assert` with a comment explaining why it's actually always true), or one of exactly 2 disclosed `# type: ignore` comments for well-known false-positive patterns (Werkzeug's standard `app.wsgi_app = ProxyFix(...)` reassignment idiom; a `dict[str, type[Base]]` factory-dispatch pattern) — nothing suppressed without either fixing it or explaining why it wasn't real. Two real findings beyond typing noise: (1) `domain/phoneme_engine.py`'s own `__main__` demo block called a function that doesn't exist anywhere in the module (`get_stress_map`) — dead code that would crash if run directly, removed; (2) `infrastructure/ai_providers/claude_provider.py` accessed `response.content[0].text` without checking the block type — safe today (no call site requests thinking/tool use) but would have raised a raw `AttributeError` from inside a vendor SDK response if that ever changed; now checked explicitly, raises a clean `AIProviderError` instead. One single-line fix (`infrastructure/feature_store.py`'s `@contextmanager`-decorated `_connection()` had the wrong return-type annotation) cascaded to resolve 13 of the 66 errors on its own. Verified: golden master byte-identical (5/5), `api.py` still boots to 44 routes, full suite 406/406 passed — zero behavior regressions from any fix. Commit `fdcad70`.
- **2c. ✅ DONE. pytest-cov.** `.coveragerc` added, `pytest-cov` in `requirements-dev.txt`. First raw run (`--cov=.`, no config) landed at 62% — misleadingly low, dragged down by ~15 files (`aave_phonology.py`, `aspiration_gap.py`, `bar_grid_linguistics.py`, `data_generator.py`, `density_gradient.py`, `device_detection_engine.py`, `ml_interface.py`, `ml/`, `model_registry.py`, `phoneme_resolver.py`, `train_rhyme_model.py`) at a flat 0% each. Checked, not assumed, before excluding any of them: grepped every one for real callers outside their own little cluster — confirmed they only import each other, never `api.py` or anything in `domain/`/`application/`/`infrastructure/`. This is the same offline ML-experiment chain `mastery_engine.py` pulls `device_detection_engine.py` from — consistent with that already-known "real code, not live" status (`docs/DECISIONS_NEEDED.md` item 2), not a new finding. All excluded in `.coveragerc` with the reasoning inline, not silently dropped. **With that honest exclusion applied: 74.5% on the actual live pipeline** (4786 statements, 1221 missed, 406 tests). Real gaps worth flagging, not fixing here (writing new tests is separate work from standing up the tooling):
  - **`wordform_engine.py` — 0%.** Not a legacy file like the ones above — this one IS live (imported by `/wordforms`, confirmed via grep), it just has zero test coverage. The one genuinely concerning number in this list.
  - `domain/syllable_compression.py` — 18.7%. Real, substantial engine (syllable-elision detection), barely exercised by the current suite.
  - `infrastructure/feature_store.py` — 34.2%. Most of the individual `write_*` functions (one per data type: phoneme sequences, lyric lines, rhyme/cadence/motif events, song sections/analyses) aren't unit-tested directly — only reached indirectly via the concurrency test.
  - `domain/performed_stress.py` — 39.5%, `thesaurus_engine.py`/`thesaurus_schema.py` — ~45% each, `api.py` — 46.7% (mostly untested error/edge-case branches across many routes, not one concentrated gap).
  These are logged here as real findings, not queued as new work — Khris didn't ask for a test-writing pass in this scaffold build, just the coverage number itself. Worth a look whenever test coverage becomes its own priority.
